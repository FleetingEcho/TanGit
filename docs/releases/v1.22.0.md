# TanGit v1.22.0

## Highlights

- **Keep your place during refresh**: quiet history updates and lazy pagination retain reading position instead of resetting filtered lists to the top. Stable identities for commits, reflog entries and remote branches, retained loaded ranges and newer-user-scroll precedence prevent background work from moving the reader unexpectedly.
- **Publish working-tree results before ancillary metadata**: accepted actions on progressive repositories publish their real, resulting file state before history, refs, reflog and worktree details finish loading. Distinct Checking and Updating states describe recovery validation and real file mutations; deferred details preserve the newer core state, with cleanup on errors and repository closure.
- **Manage caches by repository**: Settings → Cache can measure and clear a recent repository's search index without removing its recent card. Removing a repository from recent items remains a separate confirmed action. Shared or in-use project indexes stay protected, and editor recovery data and Git Safety Journals are never cleared as search caches.
- **Account for unfinished index builds**: the cache view now includes other published indexes and app-owned index staging directories as well as recent projects. Cleanup cancels builders, waits for active work and removes only directories whose ownership is revalidated; completed indexes and recovery data remain protected.
- **Clearer cache controls and navigation**: cache measurement and repository management use compact group-header actions. Closing the repository cache manager returns to Settings without a redundant second Back action; the separate whole-cache cleanup still requires confirmation.
- **Do not block merges on unrelated ignored files**: recovery preparation is scoped to actual target-related overwrite candidates. Unrelated ignored files, including legal POSIX paths containing literal backslashes, no longer prevent a merge, while genuine collisions still retain fail-closed recovery protection.
- **Open the exact failed command**: error notifications and the status error lead to the identity-bearing command-log record, with a one-time reveal. Missing or evicted records fall back to the ordinary log rather than revealing a different command with identical text.
- **Improve reading and pane interactions**: commit descriptions fit their rendered raw or Markdown content within a bounded, scrollable area, while manually chosen per-commit heights remain authoritative. Centered divider grips retain the native pane-resizing behavior.

## Compatibility and notes

- External assistants remain trusted shell commands that generate reviewable suggestions, not sandboxed providers or automatic changes.
- Conflict-resolution results, patch applications and Continue actions still require explicit approval. Real overwrite collisions, recovery checkpoints and Safety Journals remain protected.
- Supported history rewrites retain their existing single-source and non-interactive-signing limits. Stack publishing remains per branch and non-transactional.

## Platforms

Release packages and signed updater archives are built for:

- macOS universal
- Windows AMD64 and ARM64
- Linux AMD64 and ARM64

The updater signing key and the public key in `mygo.json` remain unchanged. The release workflow builds native packages, complete update archives, supported deltas and every platform's update manifest before publication.
