# TanGit v1.21.0

## Highlights

- **Cache management in Settings**: a dedicated Cache page shows total, Zoekt and avatar disk usage, with explanatory info badges and minimal/no-op-redraw refreshes. Manual refresh keeps existing numbers visible and acknowledges the new measurement with a notification. Explicit clearing is confirmed first and never touches editor recovery or Git safety journals.
- **Automatic cache lifecycle**: removing a recent card or evicting it at the history limit reclaims that repository's index and recovery cache without touching linked worktrees, submodules or caches used by other tabs. Startup cleanup removes sufficiently old orphans and bounds unreferenced index storage; cached avatars retain their LRU limit.
- **Bounded Zoekt storage**: repositories over a 256 MiB source-content budget skip expensive trigram indexing and use the complete ripgrep/native search fallback instead of producing multi-gigabyte shards. Older oversized indexes are reclaimed, no partial index is published, and slower background checks can re-enable indexing after the workspace shrinks.
- **Per-repository Zoekt switch**: Settings → Editor can disable Zoekt for one repository. Disabling asks before clearing that repository's index, explains the slower search trade-off, cancels matching builds across open tabs, and remembers the choice. Re-enabling rebuilds on demand and the search backend still honors the source budget.
- **Consistent preference controls**: boolean Settings now use a switch followed by its label, with compact grouping preserved for established layouts. Ordinary preferences change immediately; only cache-destructive actions ask for confirmation.
- **Dialog fixes**: cancelling or pressing Escape on the cache confirmation dismisses only the confirmation, not the parent Settings dialog.

## Compatibility and notes

- External assistants are trusted shell commands, not a sandbox or a wire-model provider. They only generate reviewable suggestions. No vendor or model is implied.
- SSH workspaces disable trusted local Continue test commands. Local commands may use the network and modify files in the workspace root.
- Users must explicitly approve conflict-resolution results, patch applications and Continue actions.
- History rewrites are limited to supported single-source commit workflows. Root `new-before` and non-interactive GPG signing are not supported in these workflows.
- Stack publishing is per branch and non-transactional; update-ref operations use local-CAS protection and preview-bound leases.

## Platforms

Native packages are built for:

- macOS universal
- Windows AMD64 and ARM64
- Linux AMD64 and ARM64

The updater signs and verifies update integrity with the same private key used by previous TanGit releases; the public key in `mygo.json` remains unchanged.
